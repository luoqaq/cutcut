# 抖音与小红书视频创作工作流

首次调研：2026-10-22；更新：2026-10-23。流程覆盖选题、受众、素材理解、故事结构、风格、声音、色彩、平台包装与效果复盘。已做一条宠物粗剪 v01，但完整工作流尚未跑通，没有完成账号增长实验。声音、调色与审片的新增依据见 [AI 剪辑完整流程研究](ai-editing-end-to-end-workflow-2026-10-23.md)。

## 核心判断

有相关工作流和 Agent Skills，能帮助研究参考内容、形成选题与脚本、设计封面和复盘。现有证据不能证明安装某个 skill 就能稳定做出爆款。

最值得建立的能力是：**把受众需求和真实素材变成可检验的内容假设，再用发布数据修正下一条。** 视频剪辑只是其中一个执行环节。优先复用现有剪映；策划与复盘可先采用本地文档、参考链接及用户提供的数据，无须立刻新增付费服务。

## 平台资料能确认什么

- 抖音安全与信任中心公开说明推荐系统包含用户行为预测与多目标平衡，不能把“完播达到某个数值”写成保证获得推荐的公式。[官方算法透明资料](https://trust.douyin.com/transparency)
- 抖音作者助手有针对“2s 跳出率”的正式创作课，说明开头留存是可诊断的问题；这不是要求所有内容都快剪、喊话或塞反转。[官方创作课，2025-05-20](https://jingxuan.douyin.com/m/video/7506120433238822181)
- 抖音开放平台的视频基础数据接口包含播放、点赞、评论、分享和平均播放时长；需要申请权限及用户授权，且有数据时效与视频创建时间限制。接口存在不等于本项目已接通。[官方接口](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/video-data/get-basic-data/)
- 小红书灵犀官方页面提供需求、人群、搜索与笔记洞察等商业研究功能。它证明可以围绕真实需求与搜索做内容研究，不代表普通创作者账号自动拥有相关商业权限。[官方灵犀](https://idea.xiaohongshu.com/)
- 小红书蒲公英官方帮助资料列出笔记表现中位数、完播、流量来源及日常/合作笔记分类等指标，可作为比较方法参考，不能承诺普通账号都有相同看板。[官方帮助](https://pgy.xiaohongshu.com/help/list?id=574&userType=1)

部分官方页面依赖登录或动态渲染。本次小红书灵犀及蒲公英相关字段来自官方域名的可检索正文，未进入用户账号核验界面与权限。未采用冒充“小红书中文官网”的近似域名文章作为证据。

## 一条视频的完整流程

以下采样量、备选数量和观察时间是建议工作安排，不是平台规则或统计保证。

| 环节 | 要做的判断 | 具体交付物 | 通过标准 |
|---|---|---|---|
| 1. 定义目标与风格 | 给谁看，想让他看完后做什么；希望产生什么情绪 | 内容简报与风格卡：看点、主情绪、节奏、原声/音乐、色彩和字幕方向 | 能说清看点，也能把“治愈/好笑”等形容词转成可执行选择 |
| 2. 研究参考 | 最近同题材、同形式、相近体量账号，哪些内容超出其平常表现 | 约 10–20 条参考卡：原链接、日期、账号规模、公开表现、开头、结构、评论需求 | 同时保留一般表现样本，避免只看幸存的爆款 |
| 3. 看懂素材与原声 | 哪些镜头有信息、情绪、变化和证据；缺什么 | 带时间码的镜头及声音清单、动作前后文、缺口与补拍清单；注明已看/已听范围 | 候选段连续复看；镜头能支撑选题承诺，不能靠文案编出素材里没有的结果 |
| 4. 设计结构 | 观众为什么停下、为什么继续、最后获得什么 | 一条故事主线；2–3 个开头备选；镜头出入点、台词、字幕与声音安排 | 开头有明确吸引理由，中段持续推进，结尾兑现承诺 |
| 5. 粗剪与精剪 | 故事、大致情绪及节奏是否成立；动作反应是否完整 | 带临时音乐/原声方案的粗剪；逐切点修整后的精剪；必要的开头备选 | 粗剪可判断情绪；精剪删除重复信息，保留必要停顿。音乐方向在此阶段开始比较 |
| 6. 声音精修 | 原声、音乐、音效谁主导；哪里应留白 | 原声保留清单、候选音乐比较、音乐来源及适用范围、音量与进出点 | 实际试听；音乐可感知但不盖住关键声音；无突兀剪断、爆音或不自然降噪 |
| 7. 色彩精修 | 镜头是否统一，风格是否服务情绪 | 代表镜头参考；逐镜曝光/白平衡/对比匹配；统一风格前后对照 | 相邻镜头连续播放自然；毛发与肤色合理。不以加了滤镜或改了参数代替验收 |
| 8. 分平台制作 | 不同入口下，封面、标题、开头与信息顺序是否要变化 | 抖音版、小红书版；各自封面、标题、正文与关键词 | 每版都有可解释的内容选择；运动中主体与字幕仍可读，不被当前平台界面遮住 |
| 9. 审成片与检查文件 | 第一遍是否看懂、混音是否舒服、承诺是否兑现；导出是否正确 | 导出文件完整视听审片记录、时间码问题与修改清单、独立技术检查结果 | 完整观看并实际听混音；文件可解码只证明技术状态，不能证明观感与听感合格 |
| 10. 发布与复盘 | 是曝光、点击、开头、内容推进还是行动转化出了问题 | 版本记录；发布后约 24h/72h/7d 的数据快照；下一次只改一个主要因素 | 对实际可见数据下结论；分清公开互动、后台观看和流量来源 |

没有自然语言转录时，不能把看过抽帧写成已经理解全部对白；没有完整看片时，不能把稀疏帧判断写成逐帧分析。素材分析工具与转录能力需要单独核实。

风格在开剪前规划，细节在结构较稳定后完成；声音和画面允许相互调整。交付明确标为“粗剪预览”“精修候选”或“发布候选”，说明尚缺事项。实际未听过、未完整看过就分别记录待验证，不用技术检查补足感官证据。阶段划分参考 [Frame.io](https://workflow.frame.io/guide/editing-stages)，本项目采用的风格卡、声音与色彩细则见[完整流程研究](ai-editing-end-to-end-workflow-2026-10-23.md)。

## 两个平台怎么适配

下面是实拍内容的**首轮测试策略**，不是对平台所有内容的统一规则。两平台都存在推荐与搜索，也都能承载娱乐、故事、教程与较长内容，最终应按题材和入口验证。

| 决策 | 抖音版的初始测试重点 | 小红书版的初始测试重点 |
|---|---|---|
| 观众进入理由 | 首屏直接展示变化、问题、情绪或亮点，让人迅速理解看点 | 封面与标题说清主题、适合谁、会获得什么；打开后尽快兑现 |
| 故事组织 | 删除无信息的铺垫，围绕一条变化或悬念推进；保留自然情绪与原声 | 保留可信的过程、比较、细节或体验，给观众回看和检索的理由 |
| 长度与节奏 | 按信息和情绪需要决定，不预设必须 15 秒或每两秒切镜头 | 同样按内容决定；教程可以展开，情绪短片可以简短 |
| 包装 | 标题、字幕与视频实际看点一致，首帧在无声条件下也能理解 | 封面缩略图可读，标题和正文自然使用观众会搜的词，避免堆标签 |
| 数据诊断 | 以账号实际可见的开头留存、平均观看、完成情况、分享与关注为准 | 以账号实际可见的曝光/点击、观看、收藏、关注及搜索来源为准 |

## 已确认方向：生活记录 / 宠物

用户于 2026-10-22 明确选择此方向。下面按真实日常、宠物性格及人与宠物的关系设计首轮工作流；尚未确定账号人设，也未完成整批素材分析。素材目录名“桌搭”不作为题材判断依据。

### 首轮寻找三种故事

| 类型 | 从素材寻找什么 | 一条视频的组织方式 |
|---|---|---|
| 性格瞬间 | 一个动作、表情或重复习惯，以及主人或另一只宠物的反应 | 行为 / 情境 → 反应 → 结果或余味 |
| 日常小事件 | 有起因、有行动、有结果的一件小事，例如等待出门、迎接回家 | 看点或问题 → 必要过程 → 结果 |
| 陪伴记录 | 有感染力的生活片段、环境声音、人与宠物的自然互动 | 场景 → 关系细节 → 自然收尾 |

例子是筛片方向，不代表现有视频包含这些事件。先根据实际画面选一个最成立的故事，再决定长度、字幕和音乐；保留支撑情绪的反应、停顿与原声。

### 素材盘点的重点

- 为每个片段记录时间码、主体、动作、表情变化、互动对象、事件前因后果和可用声音。
- 区分可独立成立的精彩瞬间与必须带上下文才有意思的片段，避免剪掉理解反应所需的情境。
- 优先寻找能形成辨识度的真实性格与关系；没有反转时，也可以用陪伴感或一个细微变化完成故事。
- 开头至少比较“直接给最有表现力的瞬间”与“用简短情境引出反应”两种版本，不预设所有宠物内容都要高强度快剪。

### 两个平台的首轮版本假设

- **抖音版：**测试更早展示动作或反应的开头，用最少必要交代接回事件过程，再兑现结果。观察观众在什么位置离开、是否愿意分享或关注这个宠物。
- **小红书版：**测试更完整的生活情境与关系细节，以宠物表情、互动场景和具体事件组织封面标题。陪伴内容不必硬加教程、清单或收藏理由。
- 两种结构均可在两个平台尝试；上述分工只是第一轮选择，不是平台排他规则。按发布后的真实表现调整。

### 对本项目的交付与能力优先级

完整交付链：**带时间码的素材与原声清单 → 有素材依据的选题 → 风格卡与镜头表 → 带声音方案的粗剪 → 声音/色彩精修 → 两平台预览与封面标题 → 视听审片 → 数据复盘。** 已有[宠物粗剪 v01](../edits/pet-douyin-v01/README.md)；它采用临时合成音乐和轻微画面调整，未完成实际试听与整片感官验收，不能作为完整流程已跑通的证据。2026-10-23 本轮只调研和修订流程，没有重剪或发布。

工具评估优先检验视频画面理解、事件与反应识别、原声保留、故事组织和修改成本。OpenStoryline 可作为素材语义组织的小样候选；灵造可用于研究同类宠物账号，Easel 的镜头表可借用。整套数据服务与自动运营暂不作为首条成片的前置条件，这属于当前工作流建议，不是工具效果已验证。

## 怎样检验“爆款能力”

### 发布前：比较创意，不预测确定播放量

检查目标人群是否明确、第一眼能否理解看点、承诺是否有素材支撑、中段是否重复、结尾是否兑现、标题封面是否诚实、声音是否舒服。这些可以用于淘汰弱版本；AI 给出的“潜力分”仅是启发式判断，不是受过验证的播放量概率。

### 发布后：与自己的可比内容比较

- 先记录基线：近期同题材、相近长度、相同流量类型作品的中位表现。新账号缺乏基线时，先建立小批量记录，不拿头部账号的绝对播放数当标准。
- 把公开互动与后台数据分开。别人作品的点赞/评论高，不足以知道其播放量、完播率、投流情况或涨粉归因。拿不到就记为未知。
- 曝光后的点击弱，优先检查主题和封面标题是否匹配目标人群；进入后的开头流失，检查看点出现是否太晚、承诺是否模糊；中段掉人，定位具体内容段再改。
- 收藏或关注弱，需要结合本条目标判断：宠物搞笑片不一定以收藏为目标，教程则可能需要完整步骤和可回看的信息。
- 分别保存不同平台、自然/付费流量、版本与发布时间，分批测试时尽量只改一个主要因素。不同时间发布不是严格随机 A/B 实验，不能把结果差异直接归因于唯一修改。
- 24h/72h/7d 是方便记录的观察点，不是推荐系统的固定窗口，也不据此认定内容之后不会继续增长。

## 当前能力与尚缺环节

- **本会话已验证：**FFmpeg/ffprobe 可用；剪映基础导入、分割、删除片段与导出通过短样片验证，详见[本机验收记录](../verification/jianying-2026-10-22/README.md)。
- **已有粗剪：**v01 导出通过完整解码和音轨非静音检查，画面以抽帧审阅；这些不等于实际试听、全片观看或风格质量通过。
- **可先组织执行：**内容简报、参考拆解、选题假设、脚本分镜、封面标题备选、镜头清单和基于用户提供数据的复盘。每项分析须带素材或来源依据。
- **本轮未接通：**抖音/小红书账号后台、公开内容研究服务、自动数据导入、全片转录、任何新 skill 或平台自动发布。
- **本轮没有结果证据：**用户账号增长、哪种开头表现最好、某 skill 提升了多少播放量、任何确定爆款预测。
- **电脑操作边界：**后续如需应用界面，只能用不影响用户使用的独立窗口/实例在后台进行；无法保证隔离时停止界面操作。本轮仅联网读资料和写本地研究文档，没有接管剪映或浏览器窗口。

社区方案与原始代码核查另见[平台内容 Skills 调研](platform-content-skills-2026-10-22.md)。选择以可证实的数据接入与产物能力为准，不以名字里有“爆款”、功能数量或 GitHub stars 为效果依据。
